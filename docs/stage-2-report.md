# Этап 2 — первый работающий тренажёр

## Что реализовано

- Vite + Vanilla JavaScript, HTML и CSS; данные берутся из существующих десяти JSON-файлов и `docs/curriculum.md`. Новые уроки и задания не создавались; ключи и IDs сохранены.
- Главная библиотека, глобальная верхняя панель, поисковое меню по уровням A0–B2, группировка тем, статусы готовых уроков и неинтерактивные пометки тем, уроки которых ещё не созданы.
- Адаптивный Drawer на мобильном (не более 85% ширины) и открываемая боковая панель на ПК. Поддержаны повторное нажатие, выбор урока, backdrop, Escape и базовое управление фокусом с клавиатуры.
- Прямые адреса `/lessons/{lessonId}` и `/lessons/{lessonId}/tasks/{taskId}`. Условия `prerequisites` не блокируют переход.
- Теория отображается отдельными карточками; примеры, раскрываемый словарь, Reading/Word Recognition контекст, задания и возвращение к теории доступны в уроке.
- Поддержаны все фактические типы из имеющихся JSON: `identify`, `gap`, `reorder`, `correct`, `form`, `punctuation`, `word_recognition`, `reading`, `writing`, `checkpoint`. Текстовый ввод используется там, где в данных нет вариантов с выбором.
- Для ключевых заданий проверяются точные ключи, альтернативы, типографский апостроф, явно проверенные ошибки, регистр и конечная пунктуация. Конечный список распространённых орфографических вариантов en-US принимается, если задание явно не требует британского написания. Неузнанные ответы остаются `unreviewed`, а свободный Writing никогда не оценивается сравнением со строкой.
- Статус выполнения отдельно хранится от результата ответа. Повторные попытки сохраняются. Writing имеет локальный черновик и ручную самопроверку по критериям и образцу.
- IndexedDB с версией схемы 1; экспорт/импорт JSON проверяет формат, версию, IDs уроков/заданий и статусы. Прогресс автоматически записывается при изменениях и восстанавливается после перезагрузки.

## Запуск

Требуется Node.js `20.19+` или `22.12+`. Из корня проекта: `npm install`, `npm run dev`; открыть адрес из вывода Vite (обычно `http://127.0.0.1:5173`). Production-сборка: `npm run build`, просмотр: `npm run preview`.

## Проверки

- `npm test`: 6 unit-проверок валидатора ответов, статусов и импорта/экспорта.
- `npm run test:e2e`: 30 браузерных проверок production-сборки. Проверены прямые ссылки L03 и задания 10, пропуск/возврат, неверный и верный ответ для `She ___ calm.`, черновик Writing после навигации и перезагрузки, самопроверка без искусственной оценки, меню на мобильном и ПК, альтернативный ответ, будущий урок, JSON backup, отсутствие внешних запросов и обработка ошибок JavaScript. Выполняется в Chrome/Edge или Chromium Playwright.
- `python -X utf8 scripts/validate_content.py`: исходные JSON и материалы сохраняют структурную валидность.
- `python -X utf8 scripts/check_repository.py`: проверка структуры проекта и шаблонный сканер секретов.
- `git diff --check`: пробеловых ошибок нет.

## Ограничения

- Входная диагностика пока не интерактивна; в приложении показано, что пользователь может её пропустить. Используется существующая текстовая спецификация.
- Для свободных Reading-ответов и Writing нет семантического языкового движка. Только перечисленные варианты получают автоматический статус `correct`; незнакомая формулировка не считается ошибкой и требует самостоятельной или внешней проверки.
- Подсказка показывается только при наличии поля hint в данных; текущие JSON не содержат таких полей. Задания используют текстовый ввод, потому что в текущей схеме нет интерактивных медиа-компонентов.
- Нет PWA-манифеста, service worker, офлайн-кеша, аккаунтов, backend, аудио, голоса или синхронизации между браузерами. Пользователь может перенести данные экспортом JSON.
- Это функциональный первый выпуск. Требуются независимая UX/доступностная проверка и дальнейшее тестирование на реальных устройствах.

Codex проверил сценарии в установленном Chrome; это не независимый аудит доступности или педагогическая экспертиза.
